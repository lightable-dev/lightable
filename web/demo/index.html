See what changed between two revisions of a drawing.

Lightable compares two DXF files and lists every change in plain words, not just the one inside the revision cloud.

Free and open source. Your files are read in your browser, never uploaded. Why?

1. The changes the cloud leaves out

Use case: a gearbox cover, Rev B to Rev C. Proves: Lightable finds every change, clouded or not.

  • One decision, bolts M10 → M12, made 14 changes: 8 holes Ø11 → Ø13.5 mm, the hole callout, 4 hole edges in section A-A (moved 1.25 mm) and the bolt note.
  • The revision cloud marks 1 change; 13 others weren't clouded.
  • Each one is in the list, in plain words, and a tap zooms to it.

The video above.

2. Tiny changes, exact values

Use case: a precision locating plate. Proves: changes too small to see on a print are found and given exactly.

  • 3 changes: a dowel hole moved 0.5 mm right, its dimension 80 → 80.5 mm, the position tolerance ±0.1 → ±0.05.
  • Details gives the exact values: "Object: circle (handle …), layer HOLES" and "Moved 0.5 mm right".
  • Old and new texts never print over each other: the old one is struck through beside the new.

3. Re-export noise ignored

Use case: a drive shaft, Rev D, and Rev E as a simulated re-export: new handles, shuffled order, older DXF version. Proves: only real changes are reported.

  • Rev E is simulated by the script that makes these examples, not saved by a CAD program: every handle renumbered, its objects in another order, an older DXF version (R2000 instead of R2018) and its outline split into 16 separate lines.
  • Lightable reports 1 change, the surface finish Ra 1.6 → Ra 0.8. The new revision letter and revision-table row are listed separately as revision markup.
  • The 17 objects drawn the same but written differently are listed separately as "redrawn", not as changes.

4. Block edits, shown everywhere they appear

Use case: an apartment floor plan with door, window and furniture blocks. Proves: a change inside a block is shown at every place it is used.

  • 4 changes: the door block redrawn with a thick leaf (2 changes inside the block) and one partition wall moved 300 mm (its 2 lines).
  • The block edit is highlighted at all 7 doors that use it.
  • Side by side shows Rev A and Rev B with one shared zoom.

5. Big drawings, compared in your browser

Use case: a warehouse layout: 23,181 objects in Rev A, 23,182 in Rev B. Proves: large drawings are read and compared in your browser, in seconds.

  • 3 changes found among more than 23,000 objects: a location label renamed, a rack bay moved 300 mm, a column added.
  • The time to read and compare both files is measured and shown on screen with the machine it was measured on. In the video: a MacBook Air with a 2-core Intel Core i3, while the video was being recorded.
  • On screen: how many requests the browser logged in its Resource Timing list after the files were opened (fetches, scripts, images and other resources the page loads). In the video: 0.
  • While recording, the recording tool also logged every request the browser made, through the browser's developer tools: none went to another site, and none carried a request body.

To see every request the page makes yourself, follow the steps in Check it yourself.

Why 10 changes?

The example that opens with the app, a steel bracket, says "10 changes found between Rev B and Rev C". One engineering decision changed the bracket: the bolts went from M12 to M16 for a higher load. One decision, several changes in the drawing:

  • The four clearance holes grew from Ø13.5 to Ø17.5 mm (the medium-series clearance for M16).
  • The bigger holes need more edge distance, so each hole moved 5 mm inward. The edge dimensions went from 20 to 25 mm (two dimensions) and the hole pitch from 120 × 60 to 110 × 50 mm (two more).
  • The hole callout changed from "4x Ø13.5 THRU" to "4x Ø17.5 THRU".
  • The bolt note changed from "BOLTS: 4x M12" to "BOLTS: 4x M16".

That is 4 holes, 4 dimensions, the callout and the note: 10 changes. The drafter clouded only the bolt note, so the holes a mating part has to match went unclouded. The revision letter, the revision-table row, the cloud and the triangle are listed separately as revision markup (8 items).

Works with

  • DXF from R12 to 2018 (AC1009 to AC1032), as text (ASCII) DXF, from any CAD program that exports DXF.
  • Units: changes are given in the drawing's own units (mm, cm, m, in, ft and others, from the file's units setting); a file without units gets plain numbers.
  • File size: everyday drawings open in a moment. A 50 MB drawing with 275,000 entities took 34 s to open in Chrome and 47 s in Firefox on a two-core laptop.
  • Not yet: DWG and binary DXF. Save the drawing as (text) DXF in your CAD program; Lightable says so when you drop one.

How it decides what changed

Lightable compares the drawing data, not pictures of it.

  • Each entity in Rev B is matched with one in Rev C. When the two files share their internal handles (most edits keep them), matching uses the handles first.
  • Otherwise, or for anything left over, it matches by content: identical entities, entities moved by one shared offset, the same geometry with other properties (layer, colour), and finally nearby entities of the same type and layer. A guess between several candidates is marked uncertain.
  • Numbers closer than a millionth of the drawing's size count as equal, so re-saving a file doesn't produce changes. Handles, timestamps, the order of entities and the way numbers are written are never reported.
  • Shapes saved differently but drawing the same lines (a polyline saved as separate lines) are counted as "redrawn", not as changes.
  • What is left over is added or deleted.

Measured: on 12 test pairs of scripted edits, all 28 expected changes were found, with none missed and none extra. Three pairs of the same drawing (renumbered, saved as another DXF version, re-saved by another program) report no geometry changes.

Privacy

Your files are read in your browser, never uploaded. Why that is true:

  • There is no server to receive them. lightable.dev is a static site on GitHub Pages: it only serves the app's own files and has no program that accepts uploads. The code that reads and compares your drawings runs in your browser.
  • The security policy blocks sending data elsewhere. The page's Content-Security-Policy lets it connect only to lightable.dev itself (connect-src 'self') and allows no form submissions (form-action 'none'), so the browser refuses requests to any other site.
  • The code is open source: github.com/lightable-dev/lightable. No tracking, no analytics, no cookies.

Check it yourself

  1. Open Lightable. Then open the developer tools before you choose any files (the Network tab only lists requests made while it is open):
    • Chrome: the ⋮ menu › More Tools › Developer Tools (or F12; Cmd+Option+I on a Mac). Choose the Network tab.
    • Firefox: the ☰ menu › More Tools › Web Developer Tools (or F12; Cmd+Option+I on a Mac). Choose the Network tab.
    • Safari: first choose Safari › Settings › Advanced and turn on Show features for web developers. Then choose Develop › Show Web Inspector, and the Network tab.
  2. Clear the list with the Network tab's Clear button (in Safari: Clear Network Items).
  3. Drop or choose two DXF files and wait for the list of changes.
  4. Look at the Network tab: no new request appears while the files are read and compared. An upload would show here as a request carrying your file.

Checked in Chrome 155, Firefox 158 and Safari 18.6 on a Mac. The counter in the big-drawing video counts the browser's Resource Timing entries only; the Network tab shows every request, so it is the stronger check.

Honest limits

Not compared yet (each comparison lists these too, under "What isn't compared?"):

  • text styles
  • dimension styles
  • linetype definitions; the linetype names entities use are compared
  • other tables (APPID, UCS, VIEW, VPORT)
  • drawing settings other than units ($INSUNITS) and linetype scale ($LTSCALE)
  • objects (layouts and page setups, dictionaries, groups, ...)
  • anonymous blocks (dimension pictures, ...); the dimensions themselves are compared

Lightable does not say whether a change is right, whether a drawing is ready to build from, or whether a revision cloud covers every change. It reports what differs in the data; you judge what it means.

Questions

Is it free?

Yes. Lightable is open source under the MIT or Apache 2.0 licence.

Do I need to install anything?

No. It runs in the browser on computers and phones. A desktop app can be built from the source code.

Are my drawings uploaded?

No. Your files are read in your browser, never uploaded. See Privacy for why, and how to check.

Which CAD programs does it work with?

Any program that can save a DXF file (R12 to 2018). For a DWG file, save it as DXF first.

Can it tell me whether a change is correct?

No. It lists what changed, exactly; whether that is what was intended is your call.

Send feedback

Feedback opens a GitHub issue; nothing is sent until you submit it there.
